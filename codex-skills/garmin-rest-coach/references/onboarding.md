# 个性化首次引导

仅安装 skill 不能主动开启新对话。首次调用（包括默认提示词）时检查 `profile`，缺少偏好就进入本引导。
本引导由当前 Codex 对话完成，不要求再启动 Codex CLI，不先读取健康数据来猜测用户兴趣。
首次设置也包含账号连接：用户希望网页登录时，先按 [browser.md](browser.md) 打开对应区域的官方页面，
用户登录后再设置偏好并用所选主题核对数据。不要把“安装完成”或“打开了登录页”叫作“已连接”。

## 问法

先用自然语言问两个短问题，支持自由补充；有用户输入工具可用时可使用它，否则直接在对话中询问。
若选项控件不支持多选，用文本编号回复承接多选，不把用户限制成单选。

1. **你最想了解哪些信息？可以多选。**
   - 睡眠：时长、睡眠分数、作息规律（`sleep`）
   - 恢复：HRV、静息心率、压力、身体电量（`recovery`）
   - 日常运动：运动次数、时长、记录概况（`activity`）
   - 训练：运动记录与周际时长变化；没有完整强度数据时不称为训练负荷（`training`）
   - 步数：昨天的步数与日常活动趋势（`steps`）
2. **你希望多久收到一次？** 每天 / 每周 / 每天加每周 / 仅需要时手动生成。

接着只问相关的时间：每天几点；每周几、几点。使用 24 小时制并确认时区（已有配置则直接展示）。
例如“每天 08:00，另外周一 20:00，中国时间”。不把未回复视为同意默认时间。
周报固定分析上一完整周一至周日；选择其他汇报日时明确说明仍是上一完整自然周。

目标与报告详略可以放在最后一条可跳过的问题中：例如改善睡眠/恢复/提升体能/备赛/多走动/保持健康，
以及简短版或详细版。个人睡眠目标仅在用户愿意设置时询问，不能凭此诊断是否健康。
不要索取无关的姓名、生日、地址或病史。某项指标在用户设备上缺失时说明边界，不擅自换主题。

## 保存与回显

用用户的答案调用以下命令。不要手工拼未经验证的配置，不要将登录凭据放进偏好文件。

```text
python TOOL --config CONFIG configure --topics sleep,recovery,steps --frequency both --daily-time 08:00 --weekly-day Monday --weekly-time 20:00 --timezone Asia/Shanghai --detail brief --goal recovery
python TOOL --config CONFIG profile
python TOOL --config CONFIG schedule-plan
```

`preferences.json` 只包含偏好，位于 CONFIG 的目录中。再次调用 `configure` 时未指定的设置保持原值。
回显主题、频率、具体时间、时区、报告详略。明确区分“偏好已保存”与“定时任务已启用”。

## 启用与修改任务

先展示具体、可核对的安排，再确认是否启用定时任务，以及用户是要 Codex AI 解读还是仅生成基础报告。
如果对话已经明确授权这些具体安排，不重复询问。

- 在支持调度的 Codex app 中，优先使用 app 的真实自动化工具创建/更新任务。保存返回的真实任务标识；
  使用这个标识检查、更新同一个任务，不重复创建。没有自动化工具时使用本项目的计划任务脚本。
- 自动化提示词要调用 `run` 并读取 `evidence.json`，继承偏好。当前自动化里直接解读，不再加 `--codex`。
- 本地 Windows 任务使用 installer 的 `-UseCodex` 才会启动已登录的 Codex CLI 解读，消耗其额度。
- 用户改频率/时间后，先保存偏好；检查之前创建的任务并更新，取消已不再需要的同项目任务。
  若无法访问原调度器，明确说“偏好已改，现有任务尚未更新”，不宣称生效。
- 不自动添加邮件、微信、第三方 webhook 或公开网页。第一版在本地文件/Codex 内汇报。

用户修改主题无需重新回答所有问题。请求暂停汇报时停止对应实际任务，而不是仅把文案改成“暂停”。
